## Two-List Intersection

<!-- stage: context -->
### Find The Shared Time

Two teams publish the time ranges when they can use a test environment. Within each team's schedule, the ranges are sorted and do not overlap. We need every period when both teams are available. Comparing the schedules is not a union problem: time offered by only one team must not appear in the result.

At any moment we are looking at one range from each schedule. Those two ranges may share a piece, miss each other, or touch at one endpoint. After dealing with that pair, the important question is which range can be discarded safely. A correct answer to that question turns a cross-product of comparisons into one forward pass.

<!-- stage: naive -->
### Compare Every Pair

The direct solution intersects every range from the first list with every range from the second. It is correct because it considers every possible cross-list pair, and the input contract guarantees that any reported overlap belongs in the answer.

```java
static List<int[]> intersectBrute(int[][] first, int[][] second) {
    List<int[]> result = new ArrayList<>();
    for (int[] a : first) {
        for (int[] b : second) {
            int start = Math.max(a[0], b[0]);
            int end = Math.min(a[1], b[1]);
            if (start <= end) result.add(new int[] {start, end});
        }
    }
    return result;
}
```

<!-- stage: bottleneck -->
### Most Pairs Cannot Meet

Suppose each schedule contains 50,000 short ranges. The nested loops perform 2.5 billion comparisons even when the schedules alternate and almost every pair is separated by a large gap. For example, after comparing `A = [1,4]` with `B = [2,100]`, no later range from the second list can ever meet `[1,4]`: later ranges begin after `[2,100]` ends because that list is disjoint. Yet the brute-force loop keeps comparing `[1,4]` with every later `B` range.

With `m` ranges in the first list and `n` in the second, this method costs O(mn) time. It ignores the strongest part of the contract: both lists are already sorted and internally disjoint.

<!-- stage: insight -->
### Retire The Earlier End

For the current ranges `a` and `b`, their shared closed interval can only be `[max(a.start, b.start), min(a.end, b.end)]`. It exists when the computed start is no greater than the computed end. This calculation handles containment, partial overlap, and a one-point intersection without separate cases.

The larger improvement comes after that calculation. If `a` ends before `b`, then `a` cannot intersect any later range in the second list. Because that list is sorted and disjoint, its next range starts after the current `b` ends, which is already beyond `a`'s end. We can therefore retire `a` permanently. The same argument applies symmetrically when `b` ends first.

This is **two-list interval intersection** with **end-driven advancement**. We emit the current overlap when it is nonempty, then advance the pointer whose interval has the smaller end. If the ends are equal, both intervals have expired and both pointers may advance. Each move eliminates a range using the ordering contract, so neither pointer ever moves backward.

<!-- names: two-list interval intersection, end-driven advancement -->

<!-- stage: variables -->
### Two Pointers And One Candidate

The index `i` names the unresolved range in `first`; `j` does the same for `second`. Both indices move only forward. `overlapStart` is the larger current start, and `overlapEnd` is the smaller current end. Under the closed-interval contract, the candidate is real when `overlapStart <= overlapEnd`. The result contains every finalized intersection from pairs already eliminated.

<!-- stage: trace -->
### Let The Earlier End Decide

Take `A = [[1,4],[7,10],[13,17]]` and `B = [[2,5],[6,8],[10,14]]`. The first pair shares `[2,4]`. Range `A[0]` ends at 4, before `B[0]` ends at 5, so only `A` advances. The next pair, `[7,10]` against `[2,5]`, has no overlap. This time `B` ends first and advances.

Now `[7,10]` meets `[6,8]` at `[7,8]`, after which `B` advances because 8 is the smaller end. The same `A` range then meets `[10,14]` at the single closed endpoint `[10,10]`. This is the boundary step: using `<` instead of `<=` in the overlap test would lose a valid one-point intersection. Since `A` ends at 10, it advances. The final pair contributes `[13,14]`, and `B` advances beyond its list. At that point no unresolved cross-list pair remains.

<!-- stage: code -->
### Advance The Expired Range

```java run
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

public final class ClosedIntervalIntersections {
    static int[][] intersect(int[][] first, int[][] second) {
        List<int[]> result = new ArrayList<>();
        int i = 0, j = 0;
        while (i < first.length && j < second.length) {
            int overlapStart = Math.max(first[i][0], second[j][0]);
            int overlapEnd = Math.min(first[i][1], second[j][1]);
            if (overlapStart <= overlapEnd) {
                result.add(new int[] {overlapStart, overlapEnd});
            }

            if (first[i][1] < second[j][1]) i++;
            else if (second[j][1] < first[i][1]) j++;
            else { i++; j++; }
        }
        return result.toArray(int[][]::new);
    }

    public static void main(String[] args) {
        int[][] a = {{1,4},{7,10},{13,17}};
        int[][] b = {{2,5},{6,8},{10,14}};
        int[][] expected = {{2,4},{7,8},{10,10},{13,14}};
        if (!Arrays.deepEquals(intersect(a, b), expected)) throw new AssertionError("trace case");
    }
}
```

Every iteration advances at least one pointer, so the scan costs O(m + n) time. The returned intersections occupy O(r) space, where `r` is the output size, and the scan itself uses O(1) auxiliary state. Advancing both pointers on equal ends is not required for correctness, but it avoids one comparison between an expired interval and the next range. `toArray(int[][]::new)` creates the required outer array; each emitted row is already a new array, so the result does not share mutable rows with either input.

<!-- stage: applicability -->
### When It Applies

Use this scan when both interval lists are sorted, internally disjoint, and the output asks for their common pieces. The invariant is that every pair before `i` or `j` has been resolved, while `first[i]` and `second[j]` are the only current ranges that might intersect each other. Advancing the smaller end is safe because that interval cannot reach any later range in the opposite list.

The nearest false friend is merging the two lists. Merging computes their union and deliberately preserves time covered by only one list; intersection must discard it. Another false friend is advancing the interval with the smaller start. A long interval that starts early may intersect several later ranges, so its start does not prove that it is finished.

The linear proof silently fails if either list contains internal overlaps or is not sorted. Normalize such input first, or use a different contract. Endpoint semantics also matter: closed intervals use `start <= end`, while half-open intervals use `start < end`, so touching reservations produce no common duration. Java needs no endpoint subtraction here, which avoids overflow, but the list-to-array conversion still allocates the output structure.

### Exercises

#### [Build] Intersect One Pair (Author exercise)
<!-- id: interval-intersect-one-pair -->

**Prerequisites.** Closed interval semantics and the maximum-start, minimum-end candidate described in this lesson.

**Problem.** Given two closed intervals `a` and `b`, return their intersection as a two-element array. Return an empty array when they do not intersect.

**Constraints.** Each input has two signed 32-bit endpoints with `start <= end`; target O(1) time and O(1) auxiliary space.

**Example 1.** Input `a = [2,9]`, `b = [6,12]`, output `[6,9]` because both intervals contain every point from 6 through 9.

**Example 2.** Input `a = [-5,-2]`, `b = [-1,4]`, output `[]` because the larger start is greater than the smaller end.

**Hint.** The overlap cannot begin before either interval begins, and it cannot continue after either interval ends. Which two extrema express those limits?

**Changed decision.** This first rung isolates the intersection formula before any pointer advancement is needed.

#### [Vary] One Interval Against A Sorted List (Author exercise)
<!-- id: interval-one-against-list -->

**Prerequisites.** The Build exercise and forward traversal of a start-sorted, disjoint interval list.

**Problem.** Given one closed query interval and a sorted, pairwise-disjoint list of closed intervals, return every intersection with the query in ascending order.

**Constraints.** `0 <= intervals.length <= 10^5`; all endpoints are signed 32-bit integers; target O(n) time without sorting or mutating the input.

**Example 1.** Input `query = [4,11]`, `intervals = [[1,2],[3,6],[9,12],[15,18]]`, output `[[4,6],[9,11]]`.

**Example 2.** Input `query = [20,25]`, `intervals = [[-3,0],[2,7],[9,19]]`, output `[]`; every list interval ends before the query starts.

**Hint.** Ranges ending before the query can be skipped. Once a range starts after the query ends, what does start order say about the remaining suffix?

**Changed decision.** One side stays fixed, so the scan has one moving pointer and can stop when starts pass the query end.

#### [Boundary] Touching Intersections (Author exercise)
<!-- id: interval-touching-intersections -->

**Prerequisites.** Closed and half-open endpoint contracts from the previous lesson, plus the one-pair formula.

**Problem.** Given two intervals and a boolean `closed`, return the length of their intersection. When `closed` is true, length means the number of integer points in the closed overlap. Otherwise the intervals are half-open and length means their continuous span.

**Constraints.** Endpoints satisfy `-10^9 <= start <= end <= 10^9`; compute with `long`; target O(1) time.

**Example 1.** Input `a = [1,5]`, `b = [5,9]`, `closed = true`, output `1` because the integer point 5 belongs to both ranges.

**Example 2.** Input `a = [1,5)`, `b = [5,9)`, `closed = false`, output `0` because a half-open handoff has no shared span.

**Hint.** First compute the larger start and smaller end. Which contract includes the candidate when those values are equal, and why does the closed integer length add one?

**Changed decision.** Equal endpoints now produce different answers under two explicit interval models.

#### [Recognize] Interval List Intersections (LeetCode 986)
<!-- id: interval-list-intersections -->

**Prerequisites.** The full end-driven two-list scan and closed-boundary overlap test from this lesson.

**Problem.** Given two arrays of pairwise-disjoint closed intervals, each sorted by start, return all intersections between one interval from the first array and one from the second.

**Constraints.** Each list contains at most `1000` intervals; endpoints lie between `0` and `10^9`; target O(m + n) time excluding the returned rows.

**Example 1.** Input `first = [[0,3],[7,11],[15,18]]`, `second = [[1,5],[8,10],[11,16]]`, output `[[1,3],[8,10],[11,11],[15,16]]`.

**Example 2.** Input `first = []`, `second = [[2,4]]`, output `[]` because no cross-list pair exists.

**Hint.** After emitting the current overlap, compare the two ends. Which current interval is unable to reach any later interval in the other list?

**Changed decision.** Both sides now advance independently, so each iteration must eliminate the interval whose end expires first.
